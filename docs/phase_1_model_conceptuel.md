# 🟢 Phase 1 — Conceptual Model and Security Axes

> **Historical document.** This page describes a design stage; it does not
> replace the current architecture. See `README.md` and `CODEBASE_AUDIT.md`.

The mental model of monl is extended to support isolation of AI logic and static security analysis.

## The Two Evolving Security Axes
1. **Secure by default**: The generator systematically applies industry best practices (protection against SQL injection, Pydantic type validation, scope isolation). No vulnerability can be introduced through user negligence.
2. **Secure and audited**: The compiler embeds a static security analysis engine directly in the pipeline. It actively scans the declared specification to detect dangerous structures (missing permissions, implicit privilege escalation, improperly protected sensitive actions).

## Extended Concepts
- **Entity & Attribute**: Definition of data structures and type constraints.
- **Relation**: Logical links that induce database integrity constraints.
- **Actor & Workflow**: Strict definition of profiles and their associated API routes.
- **Custom Block (AI Escape Hatch)**: Explicit declaration of the input/output boundaries of a function to be generated by an LLM in an isolated sandbox.
